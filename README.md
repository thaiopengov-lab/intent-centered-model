# Intent-Centered Model (ICM)

**Intent-Centered Model (ICM)** is a conceptual framework for preserving the **traceability of intent** in complex systems.

Modern governance, procurement, and system design processes often preserve procedures and documentation, but gradually lose the original **intent** that motivated them. When this happens, systems may appear compliant while failing to serve their original purpose.

The Intent-Centered Model proposes a structure that keeps **intent, decisions, and outcomes traceable over time**, enabling systems to maintain institutional memory and accountability.

---

# The Problem

Many complex systems suffer from a phenomenon often described as **intent drift**.

A process may begin with a clear goal:

Problem → Intent → Decision → Implementation

But over time:

- constraints accumulate
- decisions change
- actors change
- documentation grows
- the original purpose fades

The result is a system where:

- procedures remain
- documents exist
- compliance appears correct

—but the **original intent is no longer visible or traceable**.

This leads to what can be described as:

- hollow compliance
- procedural legitimacy without substantive purpose
- institutional drift

---

# Core Idea

The core idea of the Intent-Centered Model is simple:

> Complex systems should preserve the **traceability of intent** across time.

Instead of focusing only on procedures or documentation, systems should maintain traceable relationships between:

- problems
- intent
- constraints
- actors
- decisions
- requirements
- implementation
- outcomes

This allows systems to answer critical questions such as:

- Why was this system built this way?
- Which decisions changed the original direction?
- What constraints influenced those decisions?
- Do the outcomes still serve the original intent?

---

# Intent Traceability Graph (ITG)

The structural mechanism of the model is the **Intent Traceability Graph (ITG)**.

The ITG represents a network of relationships between the key elements that shape decisions in complex systems.

## Core Nodes

- **Problem** – the issue that motivated the system
- **Intent** – the purpose or objective the system aims to fulfill
- **Constraint** – limitations that influence decisions
- **Actor** – individuals or entities participating in decisions
- **Decision** – choices made during system design or governance
- **Requirement** – formalized expectations derived from decisions
- **Implementation** – the actual system built or executed
- **Outcome** – the observable results of the system

These elements form a **traceable network rather than a simple linear process**.

---

# Evolvable Intent

In the Intent-Centered Model, intent is not assumed to be permanently fixed.

Intent may evolve as:

- knowledge improves
- constraints change
- risks become clearer
- contexts shift

However, every change to intent must remain **explicit and traceable**.

The goal is not to freeze intent, but to ensure that **its evolution can always be reconstructed**.
